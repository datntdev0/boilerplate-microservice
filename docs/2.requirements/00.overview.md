# Requirements Overview

This folder holds the **baseline product requirements** — what the platform's existing
capabilities are expected to do. It describes behaviour at a high level; the source code is
the detailed, authoritative reference.

## Organization

Documents are grouped by capability, ordered from foundation upward:

| Doc | Capability | Status |
|-----|------------|--------|
| [01.platform](./01.platform.md) | Cross-cutting platform & quality attributes | Implemented |
| [02.authentication](./02.authentication.md) | Sign-up, sign-in, sessions (OAuth2/OIDC) | Implemented |
| [03.authorization](./03.authorization.md) | Users, roles, permissions (RBAC) | Implemented |
| [04.multi-tenancy](./04.multi-tenancy.md) | Tenant management & associations | Implemented |
| [05.notifications](./05.notifications.md) | Notification delivery | Planned |
| [06.payments](./06.payments.md) | Payment processing | Planned |

## Document shape

Each capability doc follows the same outline so they stay comparable:

- **Purpose** — what the capability is for.
- **Actors** — who uses it.
- **Functional requirements** — what it must do.
- **Acceptance criteria** — observable Given/When/Then outcomes.
- **Constraints & NFRs** — rules and quality attributes.
- **Out of scope** — explicitly excluded.

## Relationship to the ScrumAI workflow

These docs capture the **current baseline**. New feature work is specified, designed, and
verified through the ScrumAI workflow under `.scrumai/features/<name>/`. When a feature ships
and becomes part of the baseline, summarize it back into the relevant document here.
