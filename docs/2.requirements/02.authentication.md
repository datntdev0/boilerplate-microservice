# Authentication Requirements

## Purpose

Let users prove who they are and obtain tokens that grant access to the platform, using
standard OAuth2/OIDC flows provided by the OpenIddict identity provider.

## Actors

- **End user** — signs up and signs in through the identity provider's UI.
- **Client applications** — the Angular SPA (authorization code flow) and services (client credentials).

## Functional requirements

- **Sign up** — a new user registers with email, password, first and last name. Email must be unique.
- **Sign in** — a user authenticates with email and password; passwords are verified against a stored hash.
- **Session** — an authenticated caller can retrieve the current session (user details, roles, permissions).
- **Token issuance** — the identity provider supports authorization code (with PKCE) for the SPA,
  client credentials for service-to-service, and password grant for headless/testing scenarios.
- **Sign out** — a user can end their session and revoke server-side tokens.
- **SPA flow** — the Angular app redirects unauthenticated users to the provider, handles the
  callback, stores tokens, and attaches a Bearer token to API calls.

## Acceptance criteria

- **Given** an unused email, **When** a user signs up, **Then** the account is created and credentials are stored hashed.
- **Given** an email already registered, **When** a user signs up, **Then** registration is rejected as a duplicate.
- **Given** valid credentials, **When** a user signs in, **Then** a session is established and tokens are issued.
- **Given** an authenticated session, **When** the session endpoint is called, **Then** the user's roles and permissions are returned.
- **Given** an unauthenticated SPA user, **When** they open a protected route, **Then** they are redirected to sign in and back after success.

## Constraints & NFRs

- Passwords are never stored or logged in plain text.
- Tokens are JWTs validated by each service against the provider as authority.
- Email is the unique login identifier.

## Out of scope (today)

- Social/external login (Google/Apple buttons exist in the UI but are not wired).
- Multi-factor authentication, password reset/recovery, email verification.
