# Platform Requirements

Cross-cutting capabilities and quality attributes shared by every service.

## Purpose

Provide a consistent foundation — routing, security, persistence, observability, and a
modular structure — so each service behaves predictably and new features plug in uniformly.

## Functional requirements

- **Single entry point** — external clients reach services only through the YARP gateway,
  which routes by service prefix (e.g. `/srv-identity/...`) and forwards auth headers.
- **Token validation** — every service validates JWTs issued by the identity provider and
  rejects unauthenticated or unauthorized requests with a standard error response.
- **Permission-based authorization** — endpoints are guarded by `[AppAuthorize]` checks
  against named permissions.
- **Modular composition** — features register through `BaseModule` + `[DependOn]` and load in
  dependency order; no direct wiring in `Program.cs`.
- **Consistent persistence** — relational data uses EF Core (SQL Server); document data uses
  MongoDB. Audit fields (created/updated/by) are set automatically.
- **Database lifecycle** — schemas and seed data are applied by the Migrator before services serve traffic.

## Acceptance criteria

- **Given** a request without a valid token, **When** it hits a protected endpoint, **Then** the
  service returns 401/403 with a standardized error body.
- **Given** a request to `/srv-<name>/api/...`, **When** routed by the gateway, **Then** the
  prefix is stripped and the target service receives `/api/...`.
- **Given** a new entity is created, **When** persisted, **Then** audit fields are populated automatically.

## Constraints & NFRs

- **Security** — tokens are JWTs; services never log secrets; CORS is restricted to configured origins.
- **Multi-tenancy** — tenant scoping is applied in application/query logic (no automatic row-level filtering).
- **Observability** — traces and metrics are emitted via OpenTelemetry (OTLP); health is exposed at `/health` and `/alive`.
- **Resilience** — inter-service HTTP clients apply standard retry/timeout/circuit-breaker policies.
- **API documentation** — services expose OpenAPI; Scalar UI is available in development.

## Out of scope (today)

- Async messaging (Kafka/Outbox), gRPC, distributed caching, API versioning, rate limiting.
- Prometheus/Grafana dashboards (only the OTLP exporter is configured).
