# Architecture

## System view

External clients reach the platform through a single **YARP gateway**. The gateway routes
to backend microservices, which validate JWTs issued by the **Identity provider**
(OpenIddict). Each service owns its own database.

```
Browser (Angular SPA)
        │
        ▼
   YARP Gateway ──────────────► srv-identity   (SQL Server)
        │                       srv-admin      (MongoDB)
        │                       srv-notify      (MongoDB, planned)
        │                       srv-payment     (SQL Server, planned)
        ▼
  Identity provider (OpenIddict)  ── issues & validates tokens
```

C4 context and container diagrams live in [`docs/9.attachments`](../9.attachments).

## Key patterns

- **Modular DI** — features register via `BaseModule` subclasses decorated with `[DependOn]`.
  Modules load in dependency order at startup; don't wire services directly in `Program.cs`.
- **App service convention** — application services marked `IAppService` are auto-exposed as
  REST controllers. Routes follow method names (`Get*`→GET, `Create*`→POST, …); customize with
  `[AppRoute]` and secure with `[AppAuthorize]`.
- **Service-to-service** — synchronous HTTP via NSwag-generated proxies in
  `srcs/shared/Communication`; the gateway and proxies propagate auth headers.
- **Polyglot persistence** — SQL Server (EF Core) by default; MongoDB where document storage fits.
  Both handled by the `Migrator`.
- **Observability** — OpenTelemetry traces/metrics exported via OTLP; the Aspire dashboard gives a local view.

## Repository structure

```
srcs/
  apps/        Angular (SPA) · Identity (OpenIddict login UI)
  infra/       Aspire (orchestrator) · Gateway (YARP) · Migrator (migrations + seed)
  services/    admin · identity · notify · payment
  shared/      Application · Common · Communication · Web.Host
tests/         Common (test base + TestAuthHandler) · per-service test projects
deploy/        docker compose for local SQL Server + MongoDB
docs/          this documentation
```

### Service layering

Each service is three projects:

- `Srv.<Name>.Contracts` — request/response DTOs (shared with callers).
- `Srv.<Name>.Application` — domain logic, managers, validators, DbContext.
- `Srv.<Name>.Web.Host` — ASP.NET Core entry point, DI wiring, middleware.

### Shared libraries

| Library | Provides |
|---------|----------|
| `Common` | The modular system (`BaseModule`, `[DependOn]`), base entities, session, constants |
| `Application` | EF Core base context, base app service/manager, FluentValidation + Mapster helpers |
| `Communication` | Generated HTTP proxy clients for service-to-service calls |
| `Web.Host` | Shared hosting: auth, health checks, OpenTelemetry, exception handling, OpenAPI |
