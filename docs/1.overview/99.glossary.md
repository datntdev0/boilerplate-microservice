# Glossary

| Term | Meaning |
|------|---------|
| **Tenant** | An organization/customer in the multi-tenant system. Managed by the Admin service. |
| **User** | A person who can sign in. Owned by the Identity service; may belong to multiple tenants. |
| **Identity** | A user's login credential (email + hashed password). One user can have one or more. |
| **Role** | A named set of permissions assigned to users. Can be global or scoped to a tenant. |
| **Permission** | A fine-grained capability (e.g. `Users_Write`) checked at endpoint level. |
| **Session** | The current authenticated user plus their roles/permissions, derived from JWT claims. |
| **Module** | A `BaseModule` subclass that registers a feature's services; wired via `[DependOn]`. |
| **App service** | A class marked `IAppService`, auto-exposed as a REST controller by convention. |
| **Gateway** | The YARP reverse proxy; the single external entry point routing to services. |
| **Identity provider** | The OpenIddict server (`app-identity`) that issues and validates OAuth2/OIDC tokens. |
| **Migrator** | The worker that applies database migrations and seeds initial data. |
